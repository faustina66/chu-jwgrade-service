# 新用户配置指南

本指南面向首次部署本项目的用户。

部署分为五步：

```text
打开云服务器网页终端 → 从 GitHub 下载 → 运行部署脚本 → 查看服务状态 → 测试推送
```

部署脚本会自动创建配置文件、Python 环境和 `data/` 目录。

## 开始前准备

你需要：

- 一台云服务器，**Ubuntu 22.04 及以上**或 **Debian 12 及以上**；
- 云服务器管理后台提供的 WebShell、远程终端或 VNC 终端；
- 本项目的 GitHub 仓库地址（下一步要 clone 它）；
- 自己的教务系统学号和密码；
- PushPlus token（按下方“准备 PushPlus”完成注册并复制）。

> **必须使用受支持的系统版本。** 本项目需要 **Python 3.10 及以上版本**；Ubuntu 20.04 自带 Python 3.8，Debian 11 自带 Python 3.9，均不满足运行要求。
> 部署脚本会在安装依赖前检查 Python 版本。如果版本不符合要求，脚本会停止并提示更换系统镜像。

服务器还必须能够访问长安大学的认证和教务域名。如果日志提示“请连接校园网”或 IP 白名单拦截，说明服务器网络无法访问学校系统，继续重复部署也没有用。

### 准备 PushPlus

按下面的顺序准备：

1. 打开 [PushPlus 官网](https://www.pushplus.plus/)，或直接进入 [登录页面](https://www.pushplus.plus/login.html)，使用微信完成登录；
2. 打开 [实名认证页面](https://www.pushplus.plus/center/real-auth?source=push) 并按提示完成认证。本文更新时，页面显示的认证服务费为 **3.90 元**；价格可能调整，请以实际付款页面为准。认证规则可查看 [PushPlus 实名认证说明](https://www.pushplus.plus/doc/function/verify.html)；
3. 进入 [一对一消息页面](https://www.pushplus.plus/push1.html)，在“用户 token”一栏点击“一键复制”。部署时需要填写这个 token，请不要发给他人，也不要上传到 GitHub；
4. 关注“pushplus 推送加”公众号。打开公众号设置，进入“通知消息管理”，确认通知均设置为“接收”，并关闭消息免打扰；
5. 在公众号菜单中打开“功能 → 消息开关”，确认“接收消息”已启用。

实名认证通常只需成功完成一次，之后可以在免费额度内长期使用微信推送，无需为本项目的每条成绩通知单独付费。

如果日志显示推送成功，但微信没有弹窗或没有收到消息，请按 [PushPlus 收不到消息排查说明](https://www.pushplus.plus/doc/help/message.html) 检查上述设置。

## 第一步：进入服务器网页终端

登录云服务器管理后台，打开“WebShell”“远程终端”或“VNC 终端”，进入 root 命令行。

看到类似下面的提示，就说明已经进入服务器：

```text
root@服务器:~#
```

如果云厂商不提供网页终端，可在自己电脑的 PowerShell 中执行：

```powershell
ssh root@服务器IP
```

## 第二步：下载项目

复制下面五条命令，在服务器终端中依次执行：

```bash
apt-get update
apt-get install -y git
mkdir -p /opt
git clone https://github.com/faustina66/chu-jwgrade-service.git /opt/jwgrade
cd /opt/jwgrade
```

如果 `git clone` 长时间没有响应或提示超时，通常是服务器访问 GitHub 不畅。可以稍后重试，或使用文末的备用方案。

> 本指南统一把项目安装到 `/opt/jwgrade`。不要放在 `/home`、`/root` 或 `/run/user` 下。
> systemd 服务单元开了 `ProtectHome=true`，`/home`、`/root`、`/run/user`
> 对服务完全不可见。如果项目放在这些目录中，服务将无法启动，并可能只显示
> `status=200/CHDIR`，很难联想到是路径问题。
> 部署脚本会在安装前检查路径，并提示如何移动项目。

## 第三步：运行部署脚本

```bash
bash deploy/setup.sh
```

脚本会依次询问三项内容：

1. 教务系统学号；
2. 教务系统密码；
3. PushPlus token。

输入密码和 token 时屏幕不会显示字符，这是正常现象。脚本会自动完成：

- 创建 `config.yaml`；
- 创建 Python 虚拟环境并安装依赖；
- 创建 `data/` 状态目录；
- 创建专用的 `jwgrade` 服务用户；
- 安装 systemd 服务；
- **真实登录一次教务系统**，确认账号和解析都正常；
- 检查通过后启动常驻监控。

不要连续重复运行部署脚本。首次检查会真实登录教务系统，反复运行会消耗登录额度。

### 输入错误密码时如何处理

- 脚本会**当场再问你一遍密码**，最多重试三次，不需要重新执行任何命令；
- 重试使用**临时配置副本**，不会修改正式的 `config.yaml`；
- 部署检查结束后会自动删除临时副本，正式配置仍按每天最多成功登录一次执行。

部署时一小时最多尝试 3 次，一天最多尝试 9 次。三次用完后脚本会退出，
不会等待一小时后自动重试；请在一小时后重新运行部署脚本。

如果三次都未通过，请先在 <https://ids.chd.edu.cn> 网页版确认密码，
不要继续在终端中反复尝试。

> **看到「需要图形验证码」或「账号已被锁定」时，不要去改密码。**
> 这两种情况**不代表密码错了**。先去网页版通过验证码、或等锁定自动解除，
> 然后重新运行脚本并输入**原来的密码**。脚本可能仍然返回退出码 20，
> 因为这类情况同样需要人工介入。

### 首次检查未通过

脚本会停下来、**不会启动服务、也不会登记开机自启**，并打印退出码：

| 退出码 | 含义 | 处理方法 |
|---|---|---|
| `20` | 登录被拒绝，需要人工处理：密码错误、验证码或账号临时锁定 | 先看终端上方的具体提示。密码错误时脚本会重新询问；验证码或锁定时**不要改密码**，按上面的说明处理 |
| `21` | 配置或运行环境有问题（含 Python 版本过低） | 根据错误提示处理后重新运行 |
| 其他 | 通常是页面解析问题 | 加 `--dump` 重新运行一次，保存原始 HTML 以便排查 |

> `--dump` **不要当成常规步骤**：存下来的 HTML 里有你的姓名、学号和全部成绩，
> 排查完成后请删除该文件。

部署脚本只有在测试通过后才会启用开机自启，避免失败的部署在下次开机时自动发起认证。

## 第四步：检查服务

```bash
systemctl is-active jwgrade
journalctl -u jwgrade -n 30 --no-pager
```

正常结果应当包括：

```text
active
解析出 N 条成绩
下次检查：...
```

看到 `active` 且日志完成一轮成绩解析，就说明部署完成。

首次运行还会看到这样一行：

```text
首次运行，已建立基线：N 门课程（其中 N 门已出分），本次不推送
```

**「本次不推送」是正确行为，不是出错。** 首次运行只记录当前状态作为基线；
如果把已有的历史成绩全推一遍，你会一次收到几十条微信。
从下一轮开始，只有真正发生变化才会推送。

实时查看日志：

```bash
journalctl -u jwgrade -f
```

## 第五步：测试 PushPlus 和手机显示

部署成功后，建议发送一条虚构成绩消息，确认 PushPlus 通道和手机显示都正常：

```bash
cd /opt/jwgrade
bash tools/test_push.sh
```

这条测试消息只调用 PushPlus，不访问教务系统，也不会触发教务系统登录。它只发送一条样例成绩，收到微信消息就说明推送通道和页面显示基本正常。

脚本还会生成一份 HTML 预览：

```text
/opt/jwgrade/data/push-preview.html
```

如果 PushPlus 测试失败，先看终端中的错误提示和 PushPlus 后台发送记录，不要反复重启成绩监控服务。

## 部署完成后

服务会在后台持续运行，检测到成绩变化后自动推送到微信。

调整轮询频率、查看变更历史、更新教务密码、停止服务和迁移服务器的方法，见 **[日常使用与维护](operations.md)**。

请注意：

- **服务为 `active`，但没有收到消息属于正常情况**：没有成绩变化时不会发送通知；
- **不要为了确认服务状态而反复重启**。程序会优先恢复已有会话；如果会话已经失效，重启可能触发换票或重新登录。
  想确认状态用 `systemctl is-active jwgrade`。

## 部署脚本会自动完成的事项

部署脚本会创建 `config.yaml`、`data/`、Python 虚拟环境和 systemd 服务。
请勿将实际配置、私人笔记、成绩快照或 Cookie 上传到 GitHub。
检查运行状态时使用 `systemctl is-active jwgrade`，无需重启服务。

## 可选：加强服务器安全

本指南默认使用云服务器网页终端，并以 root 用户完成部署。项目可以在这种方式下正常运行。

如果希望进一步加强服务器安全，可以在部署完成后进行以下设置：

- 给云厂商控制台账号开启二次验证；
- 在安全组中只保留确实需要的入站端口，本项目本身不监听网络端口；
- 将 SSH 密码登录改为密钥登录。关闭密码登录前，应先在另一个终端确认密钥可以正常登录。

这些是可选的服务器加固措施，不影响本项目的基本部署和使用。

## 备用方案：服务器无法访问 GitHub

仅当服务器无法执行 `git clone` 时，才需要使用本方案。先在本地电脑下载并解压项目，然后上传：

```powershell
scp -r .\jwgrade root@服务器IP:/opt/jwgrade
```

在 Linux 或 macOS 上，将本地路径改为 `./jwgrade`。上传完成后，在服务器中执行：

```bash
cd /opt/jwgrade
bash deploy/setup.sh
```

**上传前请确认本地目录中没有 `config.yaml`、`data/` 或日志。** 这些文件包含运行配置或个人数据，不应随源码上传。

## 已有部署的服务器

如果服务器上已经存在 `/opt/jwgrade` 或 `jwgrade.service`，请勿重复执行本指南中的首次部署步骤。

请保留原有的 `config.yaml`、`data/` 和 `/etc/jwgrade.env`。其中，`data/` 保存成绩快照；如果该目录丢失，程序会重新建立基线，并且无法识别丢失期间发生的成绩变化。

升级程序、修改密码和迁移服务器的步骤，见 **[日常使用与维护](operations.md)**。
